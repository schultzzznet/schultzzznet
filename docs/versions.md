# V1.0 and V2.0: what changed

{% include tldr.html %}

{% include in-short.html %}

On 2026-11-10 I took V1.0 down and built V2.0 on the same six machines. V1.0 had run for 324 days by then, from its first commit on 2025-12-21 (Docker Swarm first, k3s from 2026-04-04, its last cluster built on 2026-09-04); [History](history.html) has it month by month. This page is the diff list: for each area, what V1.0 did, what V2.0 does today, whether that is a change, and how far V2.0 has got. It was first read against the system on 2026-11-11 (the live readings at 07:00 UTC), when V2.0 was about a day old, and every row was read again against the platform's records on 2026-11-26. No row is an uptime claim. Where V1.0 did something better I say so in the row.

**Re-read, 2026-11-26.** Every row was checked against the platform's run records, registers and manifests. Rows whose
V2.0 side moved carry the new date in their evidence; the rest keep 2026-11-11. One row was wrong on 2026-11-11: it said
database objects were pruned, and every database already carried a do-not-prune mark from the shared database component.
[Reliability](reliability.html) and [Status](status.html) hold the current state.

| Word | Meaning |
|---|---|
| **V1.0** | The retired platform of the old repository, 2025-12-21 to 2026-11-10: Docker Swarm until 2026-06-09, k3s from 2026-04-04, its last cluster built on 2026-09-04 and torn down on 2026-11-10 ([History](history.html)). It is described only as it was on the dates given. It does not run. |
| **V2.0** | The K3s home site, built on the same six machines on 2026-11-10 and 11. |
| **proven** | Seen working, on the date given in the evidence column. |
| **built** | Written and applied, but not shown to do its job. |
| **planned** | Decided or intended, not built. |
| **open** | Not decided, not done, or a known gap. |

A row tagged *(V1.0, as of 2026-11-05 to 2026-11-10)* was read from V1.0's notes in its last days; it does not mean V1.0 lasted five days.

Change types: **kept** (same idea, carried over), **changed** (a different way of doing it), **new** (V1.0 had nothing like it), **dropped** (removed on purpose), **not rebuilt yet** (V1.0 had it, V2.0 does not). Two rows (3D printing source and cost) are unchanged and outside the cluster, so they carry no status word.

The shape matters more than the totals. On 2026-11-11 most of what V1.0 had for watching, scanning and surviving a lost machine was on the not-rebuilt side. By 2026-11-26 most of the watching and surviving is rebuilt, often thinner: what is still missing is scheduled fault injection and load, host patching, a public entrance, a vulnerability tracker and the delivery guards. What is new is still about how change reaches the cluster and what it is allowed to run.
